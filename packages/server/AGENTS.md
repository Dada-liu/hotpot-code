# Working in packages/server/

- Source in `src/`, tests in `test/*.test.ts`. `src/index.ts` is the package entry, re-exporting `app.ts`, `tailer.ts`, `wire.ts`, `approvals.ts`, `usage.ts`, `static.ts`, `serve.ts`, `directory-picker.ts` and `session-manager.ts`. `src/bin.ts` is the `hotpot-server` bin (Hono REST + SSE + static hosting); it delegates to `startServer` in `serve.ts`, which the published `hotpot web` command also uses.
- May depend on `@hotpot/ai`, `@hotpot/core`, `@hotpot/orchestrator` and `@hotpot/telemetry` (all `workspace:*`); never import from `@hotpot/cli`.
- This package is the M3 service layer: REST + SSE APIs between cli and orchestrator, session management, and resume-from-log replay for reconnecting clients. The JSONL tailer (`createTailer`) is the event-bus foundation; later tasks add hono routes and the `hotpot-server` bin.
- Dependency direction is fixed: `server → orchestrator → core → ai`. Never add a reverse edge.
- `node-builtins.d.ts` must stay a superset of `packages/core/src/node-builtins.d.ts` (workspace source references pull core's sources into this package's compilation). Add new ambient declarations there, never `@types/node`.
- LLM-facing prompt text is English; code comments in Simplified Chinese.
- Plan wire events carry optional `messageIds` (the assistant messages holding the plan text). `runOneTurn` emits `plan` only after `await syncDurable()`, so subscribers receive the durable `assistant_msg` before the plan event and can hide the duplicate bubble.
- M4: `assemble()` also scans skills/prompt templates, connects MCP servers, and builds the hook chain (firing `session_start`). `/name args` messages are expanded in `send()` (unknown commands throw `PromptCommandError` → HTTP 400). New routes: `GET /api/sessions/:id/prompts` and `GET /api/sessions/:id/inbox`. `summarizeUsage` takes the feature flags and reports per-feature event/tool-call counts.
- M2: permission mode endpoints `GET/PUT /api/sessions/:id/permission` (PUT runs the shared switch path: runtime holder + durable `permission/changed` + wire `permission` broadcast; `attachById` folds `permission/changed` to restore the last user-chosen mode). Queue mutators `POST /api/sessions/:id/queue/:messageId/steer` (409 unless the turn is running, 404 on unknown id) and `DELETE /api/sessions/:id/queue/:messageId` (404 on unknown id). Text uploads `POST /api/sessions/:id/uploads` (≤512KB, no NUL bytes, 10 files/session cap, written as `<home>/uploads/<sessionId>/<counter>-<sanitized name>`). Workspace listing `GET /api/sessions/:id/fs/ls?path=` (realpath + startsWith escape check, skips dotfiles/`node_modules`, 500-entry cap). `POST /api/sessions` body is `{cwd?: string, workspaceId?: string}`; the two fields are mutually exclusive (both → 400), neither → `process.cwd()`; explicit `cwd` is resolved + stat'ed (must be an existing directory → else 400), and `workspaceId` resolves the registry record (unknown → 404) and creates the session with the record's canonical path. Built-in slash commands `/help` and `/permission` dispatch in `send()` before prompt-template resolution and answer via 200 `{reply}` from `POST /:id/messages`; `GET /:id/prompts` merges them on top with `builtin: true`. Session detail (`GET /:id`) carries `permissionMode`.
- Workspaces (W2): `SessionManager` lazily opens `openWorkspaceRegistry({home})` on first use (factory stays synchronous) and exposes thin wrappers `listWorkspaces`, `createWorkspace`, `renameWorkspace`, `removeWorkspace`, `reorderWorkspaces`, `createInWorkspace`, `pickDirectory`. `WorkspaceError` codes map to `SessionApiError`: `invalid-path`/`invalid-title`/`invalid-order` → 400, `not-found` → 404, `name-conflict` → 409, `invalid-storage` → 500. Routes: `GET /api/workspaces` → `{workspaces}`; `POST /api/workspaces {path}` → `{workspace, created}`; `PATCH /api/workspaces/:id {title}` → `{workspace}`; `DELETE /api/workspaces/:id` → 204; `PUT /api/workspaces/order {ids}` → `{workspaces}`. `create(cwd)` auto-attaches a session when the resolved path matches a registered workspace; `delete()` detaches membership after removing the log, while `archive()` keeps it.
- Directory picker (W2): `src/directory-picker.ts` provides `pickDirectory({platform?, timeoutMs?, spawnFn?})`. macOS uses `osascript ... choose folder` (user cancel in stderr → `null`); Windows uses `powershell.exe -NoProfile -STA -Command` with a `FolderBrowserDialog` script (exit 3 = cancel → `null`); Linux tries `zenity --file-selection --directory`, falling back to `kdialog --getexistingdirectory` only on ENOENT (exit 1 = cancel → `null`). Missing backend → `PickerUnavailableError`; default 120s timeout → kill + `PickerTimeoutError`. `POST /api/directory-picker/pick` returns `{path: string | null}`, 501 `{code:"picker-unavailable", error}` when unavailable, 504 on timeout, 500 on other failures; the body is ignored. Tests inject `picker` via `createSessionManager({picker})`; `directory-picker.test.ts` injects a fake `spawnFn`.
- Session deletion: `DELETE /api/sessions/:id` (running → 409). `SessionManager.delete()` reuses the `close()` teardown (deny pending approvals, stop tailer, drop from `managed`, close MCP) then removes the log file from disk; web SessionList exposes it via a per-row dropdown (two-click confirm).
- Session archive: `POST /api/sessions/:id/archive`. `SessionManager.archive()` sets a `closing` flag (the followup-drain loop stops consuming queued messages), denies pending approvals, aborts the turn, awaits `turnTail` (log writes and telemetry flush complete), then reuses the same teardown; the log file stays on disk so the session can be reopened. In the web SessionList dropdown, running sessions show 归档 instead of 删除; archiving the viewed session resets state and rebuilds the SSE connection (re-attach from disk).
- Erasable TypeScript only, `.ts` extension on relative imports, no `any`, no inline imports.
- Verify with `pnpm test`, `pnpm typecheck`, and `pnpm exec biome check` from the repo root before committing.
