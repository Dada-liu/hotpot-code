# Working in benchmarks/

- `@hotpot/benchmarks` is a development/evaluation tool. `cli` and `server` must never import it, and it must not enter the shipped tool bundle. It may import `@hotpot/core`, `@hotpot/orchestrator`, `@hotpot/ai` and `@hotpot/telemetry`.
- Never reimplement SWE-bench scoring. Patch generation is ours; pass/fail comes only from the official `swebench.harness.run_evaluation` report (`resolved_ids` / `unresolved_ids` / `empty_patch_ids`). A missing report or non-zero harness exit is a failure with the log path, never a pass.
- The M5 benchmark agent is patch-only: plain checkout, no repository dependency installation, no repository test execution, no commit. Keep the prompt suffix in `src/cli.ts` and the session-runner setup in `src/agent-runner.ts` consistent with that baseline.
- `WorkspaceProvider` (`src/workspace.ts`) is the seam for a future container runner. The upper runner must only use `prepare(instance) -> { cwd, cleanup() }`; do not leak checkout details (cache paths, git commands) into `cli.ts` or report code. `CheckoutWorkspaceProvider` uses one cached clone per repo plus a detached `git worktree` per instance; cleanup removes the worktree and prunes it.
- `capturePatch` must run `git add -A -N -- . ':!node_modules' ':!.hotpot'` then `git diff --no-color HEAD` with the same pathspec. Diffing against `HEAD` (not the index) keeps changes the agent staged with `git add`; untracked files must appear in the diff, while `node_modules` and `.hotpot` must not. An empty patch is a valid prediction and is preserved as an empty string.
- Approval is explicit allow-all, audited: build a plain `ApprovalChain`, `use(allowAllHandler)` (or `use(async () => "allow")`), wrap it with `createAuditedApprovalChain` so `approval/asked` + `approval/decided` land in the session log, and auto-approve plans via `onPlanApproval`. Do not route benchmarks through `permission.mode`; the explicit allow-all chain keeps runs zero-interruption regardless of user settings.
- Real runs use a temporary `HOTPOT_HOME` (mkdtemp per instance) so user sessions and the user telemetry install ID are untouched. Tests must not read `~/.hotpot/settings.json`; inject `Settings` and a scripted adapter.
- Reports contain instance ids, pass/fail, token counts, durations and sanitized failure reasons only. Never write prompts, replies, patches, file contents or raw absolute paths. Sanitize every failure reason through `@hotpot/telemetry`'s `sanitizeErrorMessage` before it reaches `report.json`/`report.md`.
- Benchmark telemetry is a side channel: `kind: "benchmark"`, benchmark install ID, one `benchmark_run` per instance, and no content fields. It must never throw into the runner; `createTelemetryRuntime` returning `null` means "disabled, skip".
- Tests are hermetic: scripted adapter, temp git repos, temp HOME, no network/Docker/SSH. Local and remote evaluation are covered only through `buildEvaluationCommand` and `parseOfficialReport`; do not add tests that shell out to `ssh`, `docker` or `swebench`.
- `scripts/export_instances.py` must set `HF_ENDPOINT` before importing `datasets`, keep the seven exported fields, and normalize `FAIL_TO_PASS`/`PASS_TO_PASS` to string arrays. `selectInstances` must stay deterministic for a given seed and must reject unknown explicit instance ids.
- Erasable TypeScript only, `.ts` extension on relative imports, no `any`, no inline imports; comments and README in Simplified Chinese, AGENTS in English. `.py` comments are Chinese; LLM-facing prompts are English.
- Verify with `pnpm test`, `pnpm typecheck` and `pnpm exec biome check .` from the repo root before committing.
